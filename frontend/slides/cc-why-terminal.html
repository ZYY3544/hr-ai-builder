第六篇章 · 先把工具装上：终端与 Claude Code

为什么是终端里的 Claude Code

市面上教 HR 搭 agent 的，用的几乎都是拖拽平台。这一节说清楚我们为什么不走那条路——不是因为它不好用，是因为它的天花板是别人给你定的。

两条路的区别
拖拽平台（扣子 / Dify / 各家智能体工场）终端里的 Claude Code
上手十分钟出一个能聊天的东西要装、要敲命令，第一次约半小时
能力边界平台给你划好的那些节点你的电脑能做的，它基本都能做
数据跑在平台的服务器上跑在你自己的机器上，文件不出本地
产出一个绑在平台上的配置一堆你自己的文件——可以拷走、可以给同事、可以放进作品集
学到什么这个平台怎么用agent 是怎么回事

看最后一行。平台学会了，换个平台你还得重学；这一套学会了，你换什么工具都成立——因为你学的是工具调用、上下文、权限这些东西本身。

对 HR 来说，还有两条硬理由
✓ 数据不出本地第四篇章那条红线还在：员工数据不能上传外部平台。拖拽平台天然是云端的，你的花名册要传上去才能被处理。而在自己电脑上跑的 agent，文件从头到尾没离开过你的硬盘。这一条几乎单独就能决定选型。
✓ 它能碰到你的真实工作你的活是散在几十个 Excel、几个文件夹、几份 Word 制度里的。拖拽平台碰不到这些——它只能处理你手动贴进去的东西。而终端里的 agent 可以直接读你的文件夹。
代价说在前面
这一章会劝退一部分人要装东西、要在一个黑框框里敲字、第一次多半会报错。这是真的，我不打算粉饰。
但这道坎本身就是价值的一部分——如果搭一个 agent 只需要拖几下，那它就不构成任何人的能力。你翻过去了，你和"会用 AI 的 HR"就不是一类人了。

另外，Claude Code 也有桌面版和网页版。我们这门课坚持用终端版，因为完整的文件访问、自定义工具、子 agent、钩子这些能力只有终端版才全。学会终端版，桌面版你自然会用；反过来不成立。

今天就试先不装任何东西。只做一件事：在你电脑上找到「终端」这个程序，打开它，看一眼。Mac 上叫「终端 / Terminal」，Windows 上叫「PowerShell」或「终端」。就看一眼，关掉。下一节我们就在这里面干活。
