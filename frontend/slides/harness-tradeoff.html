第七篇章 · 取舍：哪些 harness 值得造

取舍：模型升级之后，这件事还需要吗

Harness 是护城河，但不是所有 harness 都是。有一类你辛苦造的东西，下一代模型发布那天就归零了。

一个判据，问自己一句话
「模型升级之后，这件事还需要我做吗？」
✓ 值得造（模型再强也需要）✕ 别投入（升级后自动消失）
你的口径和判断规则——模型永远不知道你公司「在职」怎么算为了绕过模型某个缺陷写的补丁式提示词
权限与留痕——这是制度要求，不是能力问题把长文本切碎再拼回来的各种技巧（窗口一大就没用了）
评测与阴性对照——模型越强越要验，因为错得更像真的手工调 temperature、反复试哪种措辞更灵
你的分析模式和判断案例库——只对你这家公司有效为特定模型版本调优的复杂 prompt 模板
数据的组织方式（目录、规格、记忆分层）用户完全感知不到效果的花活

看左边这一列的共性：它们全是「关于你这家公司的事实和判断」，不是「关于模型的技巧」。这就是分界线——技巧会被内化进模型，事实和判断不会。

一个具体的对照
✕ 被淘汰的例子2023 年很多人花大力气研究「怎么让模型输出稳定的 JSON 格式」——写正则修复、写重试逻辑、试各种措辞。后来模型原生支持结构化输出，这些工作一夜归零。
✓ 越来越值钱的例子同一时期有人开始记录「我们公司什么样的候选人后来表现好」。三年下来这份记录成了独有资产，而且模型越强，它越能被用好——因为强模型能从更少的例子里学到更多。
所以你的投入该往哪放

把上面的判据反过来用，你会得到一个很清楚的优先级：

第一优先把你脑子里的东西写下来（口径、判断、分析模式、踩坑）——这是唯一会增值的资产
第二优先权限、留痕、评测——制度性要求，不随技术变化
第三优先结构和流程（目录、循环、记忆分层）——会随工具演进，但思路可迁移
最后针对某个模型的具体技巧——够用就行，别深挖
一个反常识的推论如果你只有十小时投入到 AI 上，最值钱的用法不是学工具，是把你的判断写下来。工具十小时能学个大概，判断写下来是别人抄不走的东西——而且它对下一个工具、下下个工具同样有效。
今天就试把你在上一章和这一章造的所有东西列一遍，逐个问「模型升级后还需要吗」。答"不需要"的，别再往里投时间了。
