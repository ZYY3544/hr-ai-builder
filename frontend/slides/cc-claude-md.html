CLAUDE.md：它的长期记忆

每次新开对话都要把口径重讲一遍——这是你在第四篇章反复吃过的苦。这一节把它一次性解决。

一个文件解决的问题

在你的工作文件夹里放一个叫 CLAUDE.md 的文本文件，Claude Code 每次启动都会自动读它。你写在里面的东西，等于每次对话的默认前提，不用再重复。

回想第四篇章那句话：「每次新对话，四要素重新给全，它不记得你上周说过什么。」CLAUDE.md 就是这句话的解药——你把口径写进去一次，从此它一直记得。
HR 的 CLAUDE.md 该写什么
＃ 这个工作区是做什么的 我是 HRBP，这个文件夹用来处理月度人员数据和分析。 ＃ 数据口径（重要，不要自己改） - 在职：按月末在职口径，不是发薪日 - 月中异动：业绩随人走，人数算新部门 - 部门名映射：技术中心 = 研发中心（旧系统遗留，是同一个部门） - 打卡状态里，「年假」和「年休假」是同一件事 ＃ 铁的规矩 - 所有数值计算必须写代码跑，不许口算 - 任何脚本都不许修改 data/ 目录下的原始文件，结果写到 output/ - 遇到我没规定过的情况，停下来问我，不要自己拍板 - 分析结论里的数字只能引用结果表，不许重新计算 ＃ 我怎么看数（分析模式） 1. 先看各序列人数分布，人数少于 5 的序列所有分位只做参考 2. 再看 P25（比 P90 重要，它是流失风险的先行指标） 3. 高分位离群先判断是不是历史溢价，是就说明后跳过 4. 只写能对应到动作的结论，纯描述现象一律删掉
看出来了吗——这份文件你早就写好了

本章前面萃取出的判断规则、第四篇章你写下的口径和分析模式——那些文档搬进来就是 CLAUDE.md 的主体。你前面那些看起来"只是写文档"的功夫，到这一节才变成了 agent 的一部分。

这也是这门课的一条暗线：你的护城河不在工具里，在你写下来的那些东西里。工具会换，CLAUDE.md 跟着你走。
三条实操经验
让它帮你写「根据我们刚才这轮对话，把定下来的口径和规矩追加到 CLAUDE.md」——比你自己敲快得多，而且不会漏
写具体，别写正确的废话「注意数据质量」没有任何作用。「打卡状态里年假=年休假」才有用
定期删它会越写越长，长了反而稀释重点。每隔一阵读一遍，把过时的、没在用的删掉
今天就试在你的工作文件夹里建一个 CLAUDE.md，先只写三条：一条口径、一条铁的规矩、一条你看数的顺序。然后新开一个对话，问它「我们这个工作区有什么规矩」——看它是不是真的记得。
