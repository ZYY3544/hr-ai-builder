从规则到 Prompt：判断链怎么落地

手上有一沓萃取记录，怎么变成一个能跑的东西？关键不在措辞，在于把判断拆成有先后的链条，并且每一步都吐出中间结果。

四步：从原话到 Prompt
做什么拿主线案例举例
1把原话归成「信号」 原话「没有一段是接手别人烂摊子的」→ 信号：是否有接手已有系统/团队的经历
2每个信号标：能不能读到、怎么读 能读到。判据：经历描述里出现「接手 / 承接 / 优化现有 / 重构」等词，或项目起始时间晚于系统上线时间
3排成有先后的判断链 硬性条件（学历/年限）→ 相关性（行业/职能）→ 深度信号（接盘经历）。前一步不过，后面不用跑
4写成分步输出的 Prompt 见下
最关键的设计：不要一步到结论
✕ 一步到结论 「阅读简历，判断该候选人是否符合岗位要求，输出通过/不通过及理由。」
→ 它会给你一个结论和一段理由。但错了你不知道错在哪一环——是没读到信号？读到了但判断错了？还是它压根编了一个信号？
✓ 分步输出 第 1 步：只输出读到了哪些信号（每条附原文）
第 2 步：基于这些信号逐条对照规则，输出每条规则的命中情况
第 3 步：才给结论

→ 错在哪一步一眼可见。而且第 1 步的输出可以单独验收——搜一下原文就知道它有没有编。
一个可以直接改的骨架
你是招聘初筛助手。严格按三步执行，每步的结果都要单独输出。 【第一步 · 提取信号】 逐条检查下列信号在简历中是否出现，出现的附上原文： S1 接手已有系统/团队的经历 —— 线索词：接手、承接、优化现有、重构、迁移 S2 跨部门推动的经历 —— 线索词：牵头、协调、推动 + 涉及两个以上部门 S3 ……（你的信号清单） 输出格式：S1｜是/否｜原文：「……」 ※ 原文必须能在简历中被字面搜到。找不到就写「否」，不要推断。 【第二步 · 对照规则】 R1 若 S1=否，标记「接盘经历缺失」（这不是淘汰项，是提示项） R2 …… 输出每条规则的命中结果。 【第三步 · 结论】 只允许输出三种：建议看看 / 需人工判断 / 明显不符 ※ 不要输出分数，不要输出「高度匹配」这类评价词。
注意最后两行。不让它输出分数，是因为分数会制造一种它做了判定的假象—— 而按第一篇章那条闸，判定权不能交出去。「建议看看 / 需人工判断 / 明显不符」三档都是召回结论，不是录用判断。
规则要用原话，不要用抽象词
✕ 抽象词✓ 原话改写
有较强的抗压能力有接手已有系统/团队的经历
具备良好的沟通协调能力有牵头两个以上部门共同完成的项目
学习能力强近两年主动切换过技术栈或业务领域

左边那列写进 Prompt，模型只能靠自由发挥；右边那列是可检索、可验证、可争论的。 而且右边这些恰恰来自萃取记录里的原话——所以上一节说「记原话别记归纳」，这一节就是它兑现的地方。

上线前：跟人对一遍

拿 10 份简历，让 agent 跑一遍，同时让那位老法师judge一遍，对比结果。

不一致的时候，第一反应应该是回去改规则，不是改 Prompt 措辞。 因为不一致通常说明：要么你漏了一个信号，要么你把一条「看情况」的判断硬写成了规则——这两个都是上一节的问题，不是措辞问题。

落地

分步输出，用原话，先对人再上线

  1. 三步分开输出：提取信号 → 对照规则 → 给结论。一步到结论的 Prompt 没法调试。
  2. 信号必须附原文，且能被字面搜到。这一步验收是机械的，不依赖判断力。
  3. 规则用萃取来的原话，不用抽象词。「有接手已有系统的经历」可验证，「抗压能力强」不可验证。
  4. 不让它输出分数。分数制造判定的假象，而判定权不能交出去。
  5. 先跟人对 10 份。不一致时回去改规则，不是改措辞。
✎ 待补真实素材Prompt 骨架里的信号 S1/S2 是示意。
建议替换成：铭曦引擎里真实在用的一段判断链（比如 JE 的某个评估维度、或序列划分的判据），做脱敏处理后放进来。真实的判断链一看就跟编的不一样——它会有那种「为什么这里要加一个例外」的痕迹。
