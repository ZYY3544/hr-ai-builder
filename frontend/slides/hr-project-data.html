第六篇章 · 做出你的作品：从选题到讲清楚

数据：真数据碰不得，合成数据怎么造得像

做 HR AI 作品最大的墙不是不会写代码，是拿不到数据。真数据碰不得，于是作品全变成玩具——这一节讲怎么翻过去。

场景 · 唯一能用的数据恰恰不能用

你想做薪酬带宽诊断。手上正好有公司的真实薪酬明细——这份数据你一列都不能用。

不是「最好别用」，是不能用。带出公司是数据泄露；脱敏不彻底可以反推；而且一旦你把它放进作品里， 这件事本身就成了你的减分项——任何一个懂行的人看到都会想：这个人对数据边界没有概念。

✕ 想当然的做法 「我把姓名换成 A、B、C 就行了吧？」
→ 一份 200 人的薪酬表，就算隐去姓名，只要保留部门 + 职级 + 入职年份，很多人是唯一可识别的。 这不叫脱敏，叫换了个马甲。
原理 · 三条路，只有一条走得通
路径可行性说明
公开数据集部分可行 招聘 JD、劳动法条文、公开薪酬报告能拿到。但花名册、绩效、组织架构这类公开数据集基本没有
真数据脱敏不建议 要做到真的不可反推，技术门槛比造合成数据高得多，而且你没有权限做这个决定
合成数据推荐 零合规风险，而且你能精确控制里面有什么坑——这反而是优势
造得像的关键：保留分布，不保留个体

合成数据的目标不是「假装是真的」，而是保留真实数据的统计结构，这样在它上面做出来的方法才迁移得过去。四步：

做什么怎么做
1定 schema 照着真实 HR 系统的字段来：工号 / 部门 / 岗位 / 职级 / 入职日期 / 月薪 / 年终奖 / 绩效等级 / 直属上级
2定分布 薪酬用对数正态（不是正态——高薪长尾是真实的）；职级用金字塔分布；绩效按公司常见的强制分布（如 2/7/1）
3注入相关性 这一步最关键。职级↔薪酬要强相关，司龄↔职级要中等相关，绩效↔调薪要弱相关。没有相关性的数据，一跑分析就露馅——所有维度互相独立在现实中不存在
4注入脏 见下，这一步决定作品的说服力
反直觉但极其重要：作品的说服力恰恰来自「脏」。
干干净净的合成数据做出来的东西，一眼就看得出是玩具——因为真实的 HR 数据从来不长那样。 而一个能处理脏数据的作品，证明的是你知道现实长什么样，这比代码写得好重要得多。
至少注入这三种脏
脏法怎么造 / 为什么真实
口径不一致 一部分记录的薪酬是月薪、一部分是年薪；有的含奖金有的不含。这是 HR 数据最真实的痛，也是最常见的翻车点
主数据对不上 花名册里有的人在绩效表里没有；部门名称有「技术部」和「技术中心」两种写法；同名不同人
缺失与异常 5% 左右的字段空值；几条明显异常的记录（月薪填成了年薪、入职日期在未来）
数据纪律

合成数据要显式标注，参数要有来源

  1. 永远不用真数据做作品。没有例外。这不是保守，这是这个岗位的基本职业素养——第一个考察点。
  2. 显式标注是合成的。在 README 和作品界面里都写清楚。被追问时主动说，比被发现后解释强一百倍。
  3. 分布参数要有出处。薪酬分位引用公开报告、绩效分布引用常见强制分布。有出处 = 你知道真实世界什么样。
  4. 至少三种脏。口径不一致、主数据对不上、缺失异常——把清洗这一步做出来，作品的分量就完全不同了。
