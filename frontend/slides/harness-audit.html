第七篇章 · HR 专有的两层：权限留痕与自动验收

留痕：一个 HR agent 上线的前提

通用 agent 教程不会讲这一层，因为它们的场景错了不用向人解释。而你的场景，每一个判断背后都站着一个人。

为什么这一层是 HR 独有的

一个写代码的 agent 出错了，代码跑不通，你重跑一次就好。一个筛简历的 agent 出错了，一个人的机会没了，而且没有人知道。

你早晚会被问到的问题没有留痕层时你的回答
这个人为什么被筛掉了「系统判的」——这个回答在任何一场申诉里都不成立
三个月前那批用的什么标准「应该是……我记不清了」
你们改过规则吗？什么时候改的答不上来
能证明没有性别/年龄倾向吗没有数据支撑
这四个问题不是假设。只要你的 agent 参与了任何和人相关的决定，它们就一定会来——从员工、从业务方、从法务、从审计。留痕层就是你回答它们的能力。
留什么
＃ 留痕规则（涉及人的判断，一条都不能少） 每一次对人的判断，必须在 output/audit/ 下留一条记录，包含： 1. 时间、处理对象（工号或编号，不用姓名） 2. 输入了什么材料（文件名 + 版本） 3. 当时生效的规则版本（指向 notes/calibers.md 的哪一条） 4. 判断结果，以及命中了哪几条规则 5. 每条规则命中的原文依据（必须能在原材料里字面搜到） 6. 模型和 prompt 的版本标识 ＃ 特别注意 - 判断结果只能是「建议看看 / 需人工判断 / 明显不符」三档， 不许输出分数，不许输出「不推荐」这类结论性措辞 - 最终决定由人做出后，把决定和决定人也追加到这条记录里

第 5 条是这套留痕的骨头：「原文依据必须能字面搜到」——这一条把「它凭什么这么判」从一句空话变成了可机械核验的东西。第一篇章讲的召回与判定、"让它只引用不概括"，在这里变成了合规能力。

留痕带来的第二个好处

它不只是防守。攒下来的审计记录，本身就是你最好的分析素材：

哪条规则命中率最高可能它过于宽松，或者它其实就是唯一起作用的规则
哪条规则从来没命中过写了等于没写，该删或该改
人工推翻率是多少这是你的 agent 到底有没有用的唯一硬指标
推翻集中在什么情况直接告诉你下一条该补什么规则
看最后两行：留痕层攒的数据，正好是记忆层里"判断案例库"的原料。这两层接上，你的 agent 就有了自我改进的闭环——而且改进的依据是你这家公司的真实决策，不是通用知识。
今天就试把留痕规则加进 CLAUDE.md，让它跑一批（假的）简历，然后打开 output/audit/ 看一条记录。问自己：拿着这一条，我能向一个被筛掉的候选人解释清楚吗？解释不了，说明还缺东西。
