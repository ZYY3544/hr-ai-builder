第七篇章 · Harness 是什么：agent 真正的分水岭

Harness：模型之外的那一整层

同样是 Claude 的模型，为什么 Claude Code 能干活、你自己搭的东西只能聊天？差的不是模型，是模型外面那一层。

先给定义
Harness = 模型之外，你造的一切。
它决定模型怎么规划、能调什么工具、记得住什么、产出存在哪、结果由谁来判。模型是发动机，harness 是车的其余部分——底盘、方向盘、仪表盘、刹车。

这个词的中文常译成「脚手架」，但那个译法容易让人以为它是临时的、辅助性的。实际上它是主体：一辆车里，发动机只是其中一个部件。

那句你需要记住的话
✓ 核心论断一个平庸的模型加上优秀的 harness，往往胜过裸露的更强模型。

这不是安慰话，是当前最强的那批 AI 产品共同验证的事实。Claude Code、Codex、Cursor 用的都是公开可得的模型——任何人都能调到同样的模型，但做不出同样的东西。差别全在 harness 层。

这套说法出自 Lilian Weng 2026 年 7 月的长文 《Harness Engineering for Self-Improvement》， 这一章的框架来自那篇文章，我们做的是把它翻译成 HR 能用的东西。想读原文的，那篇值得。

为什么这件事对你格外重要

模型能力正在快速拉平——今年某家领先半年，明年就被追上。如果你的东西全靠"我用了更强的模型"，你没有任何护城河。而 harness 是你自己造的：你的口径、你的判断规则、你的验收标准、你的权限设计，这些没有任何厂商会替你做。

这句话你在这门课里已经听过三遍了，只是换了名字：
第六篇章叫它知识萃取，第四篇章叫它分析模式，这一章叫它harness。它们是同一件事在不同层面的名字。
你上一章已经造了一半
你做过的它在 harness 里叫什么
写 CLAUDE.md 存口径和分析模式上下文与记忆层
摆 data/output/scripts 目录制品与状态管理
设三道闸、写安全红线权限层
小样先行、埋雷、对总数评估层

所以这一章不是从零开始学新东西，是给你已经在做的事情一套结构和名字——有了名字，你才能系统地改进它，而不是凭手感修补。

今天就试打开你上一章建的那个工作区，对照上面这张表，看看四层你各自造了什么、哪一层基本是空的。空的那层，就是你的 agent 现在最不稳的地方。
