第四篇章 · Code Interpreter 与沙箱：代码在哪跑，数据去哪了

Code Interpreter：从提问到执行痕迹

上一节的结论是「必须走代码」。这一节讲清楚：代码是谁写的、在哪跑的、你怎么确认它真的跑了。

四步，一次工具调用
1模型判断这活得算你问的是数值问题，它决定不自己答，而是调工具
2模型写代码这一步是它的强项——写代码正是语言模型擅长的事
3代码在沙箱里执行一个隔离的临时环境真的把代码跑起来，得到真实结果
4结果回到对话模型拿到运行输出，再翻译成人话讲给你听

这就是工具调用——第二篇章讲 Agent 时说过的那个能力，现在你第一次真正用上它。而且用的是最实用的那个工具：代码执行器。

分工看清楚了：模型当翻译官，代码当计算器。模型负责两头——把你的人话翻译成代码，把运行结果翻译回人话。中间那个数，全程没经过模型的嘴。
各家叫法不一样，是同一件事

Code Interpreter、代码解释器、数据分析、高级数据分析、Analysis tool……名字不同，机制一样。选工具时认能力不认名字：能不能上传文件、能不能看到代码、能不能看到运行输出。

怎么确认它真的跑了代码

这是你要养成的验收动作，只看三样：

看什么说明
有没有代码块能看到它写的那段代码，而不是直接蹦出一个数
有没有运行输出代码下面跟着执行结果，通常有独立的样式或「已分析」之类的标记
报没报错报错反而是好事——说明它真的在跑。真跑的过程一定会有失败和重试
✕ 最需要警惕的一种回答它写了一段代码给你看，然后直接告诉你结果——但中间没有任何运行痕迹。这种情况下那段代码只是「示意」，数字还是它编的。
怎么强制它走这条路

大部分时候模型会自己判断该不该调工具，但它也常常图省事直接答。所以在话术里明写一句，成本为零：

请写代码计算，不要口算。先运行代码，再把运行结果给我。 如果无法运行代码，请直接告诉我「无法运行」，不要给估算值。

第二句是关键——它给了模型一条诚实的退路。没有这句，它在跑不了代码的时候会默默改成口算，你还以为拿到的是算出来的数。

一次真实的执行痕迹长什么样

你问「算一下这份表的月薪中位数」，走工具调用时，你在界面上会看到大致这样三段：

▸ 已分析 · 查看代码 import pandas as pd df = pd.read_csv('花名册.csv') print(df['月薪'].median()) ▸ 运行结果 18750.0 它才开口：「月薪中位数是 18,750 元。」

三段缺一不可：代码 → 运行结果 → 它的话。它说的那个数，必须能在运行结果里找到。找不到，说明它在自己另说一个。

这一段值得你多花十秒

大多数人看到「已分析」的折叠条就直接跳过了。但展开看一眼，你能发现两类问题：

看到什么说明什么
代码里 df.head(50) 之类的截断它只算了前 50 行——这种事真的会发生，而且它不会在结论里提
代码里出现了你没说过的过滤条件它自己加了口径，比如悄悄剔除了空值行——这批人就从你的统计里消失了
你不需要看懂代码的每一行。你只需要认出几个关键词：有没有 head/limit（截断）、有没有 drop/filter（过滤）、有没有你没提过的数字。这三样看得懂，你的验收能力就比大部分人强了。
它耍滑头的两种典型样子
✕ 一、只写代码不运行「你可以用下面这段代码计算：（代码）……根据这份数据，中位数约为 1.85 万。」
——代码是给你看的，数字是它编的。标志是没有运行结果那一段。
✕ 二、跑了一部分，剩下的口算比如它用代码算了中位数，然后「顺便」口算了一句「大约是平均值的 0.9 倍」。凡是运行结果里没有的数字，都是它现编的。
写进流程

没有运行痕迹的数字，一律当它编的

  1. 模型写代码，代码出数字——中间那个数不许经过模型的嘴。
  2. 验收看三样：代码块、运行输出、报错。三样都没有就是没跑。
  3. 话术里给它诚实的退路：跑不了就说跑不了，不许估。
