第七篇章 · 取舍：哪些 harness 值得造

回到原点：一句可以随时问自己的话

这一章讲了四层、三个模式、一堆规则。但当你面对一个具体问题不知道该怎么办时，只需要回到一句话。

那一句话
「我现在给它的东西，
是它做好这件事所需要的全部吗？」

它不知道你的口径 → 补进 CLAUDE.md。
它记不住上个月的结论 → 建记忆层。
它拿不到某份材料 → 给它工具或把文件放进工作区。
它不知道什么算做对了 → 给它验收标准。
它不知道哪些事不能做 → 写红线。

你会发现这一章所有的内容，都是这一个问题的不同答案。harness 的每一层，本质都是在补齐"它需要但还没有"的那部分。

但要小心一个陷阱
「所需要的全部」不等于「越多越好」把所有东西一股脑塞给它，效果反而更差——重点被稀释、无关信息干扰判断、成本还高。
是「所需要的」，不是「你有的」。这也是记忆层要分层的原因：该在眼前的在眼前，该能查到的能查到，两者不能混。
这门课到这里，其实一直在讲同一件事
篇章它在补哪一块「它需要但没有的东西」
第一篇章 幻觉与边界先搞清楚它天生缺什么、哪些缺口补不上
第二篇章 Prompt 与 Agent怎么把意图说清楚、什么时候该给它自主权
第三篇章 术语祛魅听懂那些词，判断哪些你真需要、哪些只是在唬你
第四篇章 Code Interpreter给它算数的工具，和你看数的方式；口径写成它能执行的规格
第五篇章 Vibe Coding协作的纪律——让它写得快也写得稳
第六篇章 Claude Code给它一个能真正干活的工作环境
第七篇章 Harness把以上全部组织成一个能持续运转、能被追溯、能自我改进的系统
所以这一章不是新知识，是收口。前面每一章你造的东西，在这里各就各位。

后面还有两章，讲的是另一半问题：东西造出来了，怎么让人真的用起来（第八篇章）、怎么让它拿得出手（第九篇章）。
最后一件事

Harness 这个概念还很新，它本身也在快速演进——Lilian Weng 那篇文章的后半部分讲的是「让 agent 自己改进自己的 harness」，那是研究前沿，我们没讲。但你不需要追那个前沿，因为对你来说，最值钱的那一层永远不会变：

✓ 记住这一条就够模型是租来的，harness 是你自己的。模型每半年换一代，你的口径、判断、案例库、验收标准，是跟着你走的。
这也是这整门课想告诉你的唯一一件事。
第七篇章到此收束。你现在能造出一个稳、可追溯、会自我检查的 agent。下一篇章是最后一关，也是最难的一关——它在你电脑上跑得好好的，怎么让它在一个有制度、有审批、有既得利益、有人不想改变的组织里，真的活下来。
