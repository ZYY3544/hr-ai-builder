第四篇章 · 生成 vs 执行：它给的数是算的还是猜的

它在预测 token，不在做运算

不是模型「不够聪明」，是这件事从机制上就不是它干的活。理解这一层，你就知道该在哪里设防。

数字进到模型里长什么样

模型读文本时，会先把文本切成一个个 token（词元）。汉字和单词是这么切的，数字也是——一个「1234567」在模型眼里可能被切成「123」「456」「7」三块，而不是一个数。

然后它做的事情，是根据前面的内容预测下一个 token 最可能是什么。你问它中位数，它是在生成一串「看起来最像中位数」的 token，而不是把数列排序取中间那个。小数据它常能蒙对，因为训练时见过大量类似的算式；数据一多、位数一长，就开始漂。

一句话：它不是算错了，它压根没算。它在写一个像答案的东西。
再叠上一层随机

就算同一个问题、同样的上下文，模型每次生成也不完全一样——这是采样带来的随机性，也就是第一篇章讲过的 temperature 在起作用。所以你会看到实验里「三遍三个数」：机制上它就不保证复现。

代码正好相反：同一段代码、同一份数据，跑十遍是十遍一样。这个性质叫可复现，是所有能拿去交代的数字的最低要求。

还有两个更隐蔽的坑
坑现场
截断是静默的表太长超出上下文窗口时，它不会说「我只看到前 40 行」。它拿看到的部分照样给你一个完整答案，语气和看全了时一模一样
专业措辞是伪装「从分布特征来看，高分位存在明显离群……」——越专业的表达越让你放松警惕。第三篇章口径那节讲的是同一件事
顺带一个架构差别：贴表 vs 传文件

把表格粘贴进对话，整张表都会变成 token 进入上下文窗口——又占地方又可能被截断。把表格作为文件上传让代码去读，文件内容不进上下文，代码直接从磁盘读，几万行也不怕。

所以「让它写代码」不只是为了算得准，顺带解决了大表根本塞不进去的问题。

记住这一条

看到 AI 给的任何数字，先问一句：这个数是代码算的，还是它嘴里说的

  1. 它在预测 token，不在做运算——小数据蒙得准，大数据必漂。
  2. 采样有随机性，机制上就不保证同一个问题给同一个答案。
  3. 截断和算错都不会报错，你看到的永远是一个完整、自信、专业的答案。
  4. 看不到代码和运行痕迹的数字，一律当作它编的。
