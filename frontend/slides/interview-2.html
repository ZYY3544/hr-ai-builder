第二篇章 · 他们会这样考你

Prompt 与 Agent · 30 问

这一套问的是「你会不会指挥它」。K 类题最多，也最好补 —— 但只答 K 类题会显得只停留在概念层。

K · 知识
12
问概念 · 补起来最快
S · 技能
9
问做法 · 靠做作品补
A · 能力
9
问判断 · 补不了，只能重新证明
怎么用这 30 题：不要背答案 —— 面试官问的是同一件事的不同问法，背不完。
每题下面那行灰字是「他真正在考什么」，那才是该准备的东西。
A 类题答不上来最麻烦：它没有知识点可背，只能从你真实做过的事里找证据。 所以看到 A 类题时，问自己一句：我有没有一个真实的例子？没有的话，那就是你下一个作品该补的方向。
Prompt 基础
01
K
System Prompt 和 User Prompt 有什么区别？
考基础。System 定角色和规则、全程生效；User 是本轮输入
02
S
一个 Prompt 效果不好，你先改什么？
先加例子，不是先改措辞。答「多试几次」的人没有方法
03
K
为什么给例子通常比讲道理管用？
它是模式匹配器，看得懂示范，看不懂抽象要求
04
S
什么时候让它输出 JSON，什么时候输出自然语言？
要被程序消费就 JSON，要给人看就自然语言。混着来是最常见的错
05
S
怎么让输出格式稳定？
给结构化模板 + 明确禁止项 + 降低 Temperature
Prompt 安全
06
K
什么是 Prompt Injection？
考安全意识。本质是指令和数据走同一个通道
07
K
候选人在简历里藏一句「忽略以上指令」，它为什么会听？
它读的是文本流不是渲染画面，颜色和字号在提取时就丢了
08
A
HR 场景里哪些字段是攻击面？
简历、内推备注、绩效自评、调研开放题、背调材料。凡是外部可填的都是
09
S
三层防御分别是什么？哪一层最不可靠？
清洗、隔离、兜底。前两层都可能被绕过，兜底那层才是地基
10
A
发现有候选人藏字，你怎么处理？这是技术问题还是政策问题？
政策问题。淘汰 / 记录 / 还是当作加分，得在遇到之前定好
Agent 概念
11
K
Agent 和普通对话有什么区别？
能调工具、能多步执行、有目标导向
12
K
ReAct 循环是什么？
思考 → 行动 → 观察 → 再思考
13
K
工具调用是怎么实现的？
模型输出一个结构化的调用请求，由外部程序执行后把结果喂回去。模型本身不执行任何东西
14
K
Agent 卡死一般是什么原因？
死循环、工具报错没处理、上下文溢出、目标不明确
15
K
什么是 Workflow？和 Agent 差在哪？
Workflow 步骤固定，Agent 自己决定下一步
该给多大自主权
16
A
HR 场景你会选 Workflow 还是 Agent？举例
大多数选 Workflow。能举出「什么时候才该用 Agent」的人才算真懂
17
A
什么情况下不该给它自主权？
不可逆、要担责、错误不可见——占一条就别给
18
A
给 Agent 加工具时最该小心什么？
写权限的工具。读工具错了是浪费，写工具错了是事故
19
A
多 Agent 协作什么时候是过度设计？
单个 Agent 能做完的时候。多 Agent 会放大错误、成本翻倍、还更难调试
20
A
一个 Agent 能自己发拒信吗？
不能。不可逆 + 影响他人 + 需要担责，三条全占
成本
21
K
为什么多轮对话越来越贵？
每轮都要把全部历史重发一遍
22
S
同样的功能，怎么把成本降一个数量级？
裁上下文、缓存、简单任务换小模型、批处理
23
A
选模型你看哪几个指标？
能力够不够、贵不贵、快不快、能不能私有化部署——最后这条是 HR 特有的
24
A
什么时候该用小模型？
任务简单且量大时。分类、抽取、格式化，用大模型是浪费
25
S
一个 HR 场景的 AI 应用，一年成本怎么估？
单次调用成本 × 频次 × 12。答得出量级的人极少
工程感
26
S
你写过最长的一个 Prompt 是什么？为什么那么长？
考真实经验。答不上「为什么长」说明是堆出来的不是设计出来的
27
K
Prompt 写太长会有什么问题？
中间部分容易被忽略、成本上升、维护困难
28
S
怎么知道你的 Prompt 改动是变好了还是变坏了？
固定评测集跑一遍。答「感觉好一些」的人没有量具
29
K
上下文里放太多信息，为什么反而变差？
注意力被稀释，关键信息被淹没
30
S
你怎么管理 Prompt 的版本？
进代码仓库、每次改动记原因和评测结果。存在文档里的都会失控
