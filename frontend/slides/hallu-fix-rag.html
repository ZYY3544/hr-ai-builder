第一篇章 · 幻觉的四种应对

应对 2：让它只答制度里有的

HR 视角：什么场景必须上 RAG，什么场景直接贴文档就够了。

手段 02 / 04 · 预防
选择业务场景
场景 A · 法律 / 合规
劳动法 / 地方社保政策助手
社保基数、公积金比例每年调，各地口径还不一样；模型训练数据有截止日期，极易引用已废除的旧标准。
场景 B · 薪酬福利
薪酬政策 / 福利细则助手
每家公司的职级带宽、补贴口径、计算方式都不一样，模型的通用知识对不上你们的制度原文。
场景 C · 制度手册
员工手册 / 流程问答机器人
制度每年修订，审批流、报销标准、考勤规则频繁变化，模型只记得训练时的旧版本。
决策框架：什么时候必须上 RAG？
✅
知识时效性强：政策/产品/价格频繁更新，模型训练数据赶不上
✅
私有知识库：公司内部文档、产品手册，模型根本没见过
✅
答错代价高：薪酬、社保、劳动关系场景，错一句可能引发劳动争议
⚠️
闲聊/创意场景不需要：RAG 反而让回答更死板

无 RAG：闭卷考试
问题 → × 训练记忆推断
前文只有问题本身，模型只能靠训练数据里的印象来推 Token
有 RAG：开卷考试
真实文档片段 + 问题 → ✓ 准确回答
检索到的文档成为前文的一部分，直接影响每步 Token 的概率分布
模型本质是 Token 推 Token，推出什么取决于前文是什么。 RAG 就是「用检索到的真实文档作为高质量前文」注入上下文： 相同的模型，前文换了，后文的概率分布就变了。 模型没有变聪明，只是有了一个更好的起点。
⚠ 局限性：RAG 不是银弹
检索本身可能出错
检索召回的文档片段不准确时，模型会把错误文档当作真实依据，幻觉不但没减少，还多了一个权威出处的外衣
模型仍会脑补文档外的内容
检索到的上下文窗口有限，超出范围的部分模型仍会用训练记忆补全，RAG + 幻觉混合输出，比纯幻觉更难被用户识别
应对策略
RAG 的质量上限 = 知识库质量。需要建立检索命中率评测，同时用引用来源强制显示让用户可核查
