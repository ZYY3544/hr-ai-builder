Takeaway
Takeaway　Agent 的工作方式是一个「思考 → 行动 → 观察 → 再思考」的循环。一个复杂任务可能循环十几轮。这就是 Agent 和普通聊天机器人的本质区别：它会根据执行结果调整策略。
ReAct 在 HR 场景长什么样

ReAct = Reason（想）+ Act（做）+ Observe（看结果），然后再想。用一个真实的活举例——「帮我看看这个月技术部的离职情况」：

想：我需要先拿到这个月的离职名单，再看部门和司龄分布 做：读取 data/2026-08/离职清单.csv 看：拿到 12 条记录，但没有部门字段 想：部门信息不在这张表里，得从花名册关联 做：读取 data/2026-08/花名册.csv，按工号关联 看：关联上 11 条，有 1 条工号在花名册里找不到 想：这 1 条可能是月中入职又离职的，或者工号格式不一致 做：检查该工号的格式和前导零 看：确实是前导零问题，补齐后关联上了 想：数据齐了，现在按部门和司龄分组 做：分组统计 看：技术部 5 人，其中 4 人司龄在 2~3 年 → 给出结论

注意第三轮：它自己发现了问题、自己提出假设、自己验证。这就是 ReAct 跟"一次性回答"的根本差别——它有机会纠正自己。

这对你意味着两件事
① 循环是可见的，所以可以验收你能看到它每一步在想什么、做了什么、拿到什么。某一步的"看"和你的预期不符，你当场就能叫停——而不是等最后结论出来才发现不对
② 它会犯错，但错误会被下一轮接住上面那个前导零的问题，一次性回答会直接给你一个少一个人的结论，而且不说
所以看到它的思考链变长、开始报错、开始改方案，那不是它笨，那是它在工作。真正该警惕的是相反的情况：一个复杂任务，它一步不做直接给结论。
你能对循环做的三件事
设上限「最多重试 3 次，还不行就停下来告诉我卡在哪」——防止它在一个死胡同里绕
要求它报告「每一步都告诉我你在做什么、拿到了什么」——第七篇章的自查循环就是从这里长出来的
允许它问「遇到我没说清的，停下来问我，不要自己假设」——这一句能挡住大部分静默出错
今天就试下次让 AI 做一个多步骤的活，把它的思考过程完整读一遍（别只看结论）。你会发现它中途做过一些你不知道的决定——那些就是你下次该写进约束的地方。
