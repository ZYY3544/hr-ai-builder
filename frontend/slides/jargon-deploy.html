开源与私有化部署：数据不出内网那条路

「私有化部署」是 HR SaaS 采购里最高频的一个词，也是最容易被含糊过去的一个。这一节把它拆开。

三个词，先分清
闭源模型Claude、GPT、豆包这类。你通过网络调用，模型在对方手里
开源模型DeepSeek、Qwen 这类把模型文件公开的。你可以下载下来，装在自己的机器上跑
私有化部署把模型装在你们公司自己的服务器上。数据全程不出内网
注意一个常被混淆的点：私有化部署 ≠ 微调。前者是"装在哪儿"，后者是"改不改模型"。供应商说「我们支持私有化部署」时，模型本身通常一点没改。
参数量：7B、70B 是什么意思

B = billion，十亿。7B 就是七十亿个参数。粗略说：参数越多越聪明，但也越吃硬件。

规模大概能干什么要什么硬件
7B 左右格式转换、简单问答、分类打标一台配置好点的电脑就能跑
30B~70B能做像样的制度问答、文档理解专业显卡，几万到几十万
顶级闭源模型复杂推理、长文档、多步任务买不到，只能调 API
你要接受的一个现实能私有化部署的模型，能力明显低于你在网页上用的那个。这不是供应商坑你，是物理限制——顶级模型的硬件成本不是一家公司扛得住的。
所以真正的问题不是"能不能私有化"，是"降级之后还够不够用"。
HR 该怎么选：先分数据，不是先分场景
数据走哪条路
员工花名册、薪酬、绩效、身份信息只能私有化或本地，这是第四篇章那条红线
公开制度、通用问答、你自己写的方案草稿直接用闭源模型，能力更强
脱敏后的数据都行，看效果和成本
✓ 一个很多人没想到的组合敏感数据用私有化模型处理，处理完的结论用强模型分析。
比如：本地模型把花名册清洗、脱敏、算出分位；把这些不含个人信息的统计结果拿给强模型做分析和写报告。
——这跟第四篇章的两段架构是同一个思路：数据留在里面，判断借外面的脑子。
听到「私有化部署」，反问这四句
1. 部署的是哪个模型？多大参数？跟我们现在用的那个比， 能力差多少？有没有在我们场景上的对比数据？ 2. 硬件谁出？一次性投入多少？谁来维护？ 3. 模型要不要定期更新？更新的时候数据会出内网吗？ 4. 除了模型本身，日志、向量库、缓存这些也都在内网吗？ ——有些方案只把模型放进来，检索还在云上

第 4 句最容易被含糊过去，也最要命：「模型私有化」不等于「数据不出网」，中间还有一堆环节。

今天就试如果你们正在谈任何一个"私有化部署"的方案，把第 1 句和第 4 句发过去。这两句问完，方案的成色基本就清楚了。
