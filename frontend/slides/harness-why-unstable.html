第七篇章 · Harness 是什么：agent 真正的分水岭

四种不稳，四层缺失

上一章那个 agent 能跑，但你多用几次就会遇到问题。这一节把症状和病因对上——每一种不稳，都对应 harness 里缺的一块。

四种症状，你多半已经遇到了
症状缺的是哪一层这一章哪节讲
① 同一个活，这次做对了下次做错
你没改任何东西，它自己变了		循环层——它没有自我检查的环节，做完就交，对不对全看运气模式一：工作流循环
② 聊着聊着它忘了前面说过的
你上周定的口径，这周它又问一遍		记忆层——重要的东西留在对话里，对话一长就被挤出去了模式二：文件系统做记忆
③ 活一复杂它就乱
让它同时处理三张表，它顾此失彼		分身层——一个上下文里塞了太多任务，互相干扰模式三：子 agent
④ 它做的事你不敢给别人看
不知道它中间干了什么、依据是什么		留痕层——过程没记录，结果无从追溯HR 专有：权限与留痕
一个具体的现场
✕ 症状 ② 的真实样子周一：你跟它说清楚了「在职按月末口径」，它照做，结果对。
周三：新开一个对话让它算另一批数据，它用了发薪日口径。
你问它为什么变了，它说「抱歉，我按常见做法处理了」。

它没有说谎，它是真的不记得——那句口径在周一那个对话里，而这是一个新对话。

解法你已经知道了：写进 CLAUDE.md。但这只是记忆层最浅的一层。更深的问题是：那些不适合写进 CLAUDE.md 的东西——上个月的分析结论、历史上踩过的坑、三十份岗位的判断记录——它们塞不进去，又必须能被用上。这就是模式二要解决的。

一个反直觉的判断
遇到 agent 不稳，大多数人的第一反应是「换个更强的模型」或者「把 prompt 写得更详细」。
但看上面那张表：四种症状没有一种是靠换模型能解决的，也没有一种是靠 prompt 写得更长能解决的。它们都是结构问题，得用结构来解。

这就是"agent 拼的是 harness"这句话的实际含义——它不是一个宏观论断，它是你排查问题时的第一诊断方向。

今天就试回想你上一章那个 agent 用得最不顺的一次，对照四种症状认领一个。认领完先别修——带着这个具体问题读后面三节，每一节都会给你对应的解法。
